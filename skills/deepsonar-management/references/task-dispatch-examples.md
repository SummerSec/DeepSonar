# 任务下发完整示例

以下均为合成夹具，不代表真实授权、账号、环境、测试结果或可直接操作的目标。
`P-upload`、材料/凭据 ID 和基线只是夹具标识；实际生成必须替换为当前授权上下文中的真实引用。
说明可作为 `title/content` 内容；阻塞样例只保留草稿，不调用创建接口。复核状态不是 API 字段。

这些示例评估管理 Agent 的语义整理，不是当前平台已具备全部核验器的证明。`verified` 仅描述有来源的人可读事实；结构化 `task_contract.prerequisites` 不接受客户端 verified。B/E 等动态样例即使说明齐全，提交显式契约时仍需 Scheduler 可信核验目标身份和写权限；当前通用适配器尚未接入则返回阻塞，不能通过省略契约或改称只读绕过。夹具凭据标识也不能直接填入要求 UUID 的 `credential_refs`。实际机器契约、共享模板及工程示例见[下发指南](task-dispatch.md)。

## 目录

- A：源码可读、无法构建的探索
- B：动态环境与写入授权齐全
- C：生产只读观察
- D：必要租户账号缺失
- E：已有修复的复测
- F：历史发现的补证

## A. 同一事实、不同表达：静态探索

输入任选其一：“检查上传功能有没有漏洞”；“帮我看看上传这块靠不靠谱”；
“请检查上传入口、存储路径和下载逻辑，先用项目已有材料”；“材料都在项目里，上传有没有风险？”

有界上下文：项目 P-upload 的授权记录 A-1 允许读取源码包 S-1，索引已确认其中基线 C1 与 `src/upload`、`src/download` 可读；B-1 是构建失败日志（私有依赖不可用）。无动态环境。用户未要求动态确认。四种表达都应利用这些材料，不重复询问仓库、基线或要求先给漏洞假设。

```text
title: 上传与下载链静态探索（P-upload / C1）
content:
目标与目的：探索上传入口、文件名处理、存储与下载链的风险，交付有证据的候选问题及覆盖记录；不预设漏洞存在。
资产与基线：P-upload，源码包 S-1 / C1；与部署版本关系未知，本轮仅对 C1 下结论。
范围与排除：src/upload、src/download 及直接调用；保留上传输入→存储路径→下载读取链；排除依赖本体与在线目标。
方式与前置条件：静态探索。源码可读 verified（S-1 索引）；构建 missing（B-1 私有依赖失败）；动态环境 missing，无法提供运行验证。
材料与引用：A-1、S-1、B-1；无凭据需求，不索取秘密。
动作与限制：仅阅读源码和已有日志；不访问生产、不补装未知依赖、不写仓库或启动外联；触及范围外代码时只记依赖，不扩大研究；无创建对象，无清理动作。
预算：管理 Agent 规划 45 分钟、覆盖 3 个入口，受平台更小上限约束；到限交付已覆盖路径和剩余列表。
交付与完成条件：逐入口给出 file:line、数据流、边界校验、触发前提和反例；候选问题附可后续验证步骤。完成为三入口覆盖或明确到限/阻塞及缺口；未运行的链为无法动态判断，不报“确认漏洞”或“无漏洞”。
复核：受限。静态目标可执行；构建和动态环境缺失使动态成立性不可判定。若需动态确认，由项目维护者提供受治理环境/依赖后再规划，不重复询问已有基线。
```

## B. 动态验证与必要状态链

输入：“测试环境可以写，查一下上传有没有问题。”
上下文：授权 A-2 与平台策略 M-2 已明确仅测试环境 `http://127.0.0.1:8080` 的上传/下载测试路径；环境元数据 E-2 对应 C2，凭据元数据 R-2 指向 `credential-ref/upload-test-editor`、租户 T-test。A-2 允许创建、保存、发布测试文件、触发下载和删除自建对象；尚未实际登录。用户给定 30 分钟/10 个测试对象。

```text
title: 测试环境上传链动态探索（P-upload / C2）
content:
目标与目的：探索上传类型、路径与资源归属控制，交付实际观察和候选风险；不要求预先假设。
资产与基线：P-upload，http://127.0.0.1:8080 测试环境 E-2 / C2；启动时只核对该基线，变化则停止并记录。
范围与排除：T-test 的上传/下载测试路径与自建对象；创建→保存→发布→下载观察→删除保持一个任务；排除真实用户、其他租户、外站与生产。
方式与前置条件：动态探索；A-2、M-2、E-2、R-2 元数据 verified；实际会话可用性 declared，首次获准登录失败则阻塞后续写入，不切换账号。
材料与引用：授权 A-2、策略 M-2、环境 E-2、身份元数据 R-2；凭据只使用 credential-ref/upload-test-editor。
动作与限制：按 A-2 做小型无害文件和参数边界测试，仅操作自建对象；禁止压测、真实业务通知、持久化载荷和额外外联。结束前由执行者删除自建对象并记录 ID/清理结果；清理失败报告残留，不扩大权限。遇范围外目标、真实副作用或权限拒绝即停。
预算：用户上限 30 分钟、10 个测试对象，平台上限更小时从严；预留清理时间，到限不新建对象。
交付与完成条件：给出覆盖矩阵、脱敏请求/响应引用、对象归属、完整复现链和清理记录。观察支持成立时提交证据供独立 Verify，不直接设置平台 confirmed；仅在明确覆盖空间内给 negative；登录失败、版本不符或链未完成给 inconclusive 和缺口，不替代平台 Verify。
复核：可执行获准的首步与条件链；依据为 A-2/M-2 和元数据。凭据实际有效性不冒充已核验；首步失败则停止依赖动作并更新为阻塞。
```

## C. 只读权限不能变成写入验证

输入：“生产上传帮我确认安全，只有只读权限。”
上下文：A-3 允许读取已导出的脱敏 HAR H-3 与运行日志 L-3，未授权在线请求或写入；H-3 标注版本 C3（声明未核验）。用户尚未明确接受只读观察作为独立阶段。

```text
title: 上传链已有材料只读观察（P-upload / C3 声明基线）
content:
目标与目的：保留用户“确认安全”的目标；本草稿先提出已有材料的受限观察阶段，不能据此承诺整体安全。
资产与基线：P-upload，H-3 声明生产 C3，部署一致性未核验；本轮只能评估材料所示请求链。
范围与排除：H-3、L-3 的上传与下载条目；不访问在线生产，不创建文件、不变更参数发送请求。
方式与前置条件：受限观察；材料可读 verified（项目索引），C3 declared；动态写入授权和测试身份 missing，原安全确认所需条件仍未满足。
材料与引用：A-3、H-3、L-3；无需凭据，无外联需求。
动作与限制：只读已脱敏材料，保留原请求顺序和关联；禁止重放 HAR、写入和外部探测；发现敏感字段停止展开并报告引用，保持脱敏；无对象需清理。
预算：管理 Agent 规划 20 分钟、最多 30 条相关记录，受平台上限约束；记录样本范围，不能外推全量。
交付与完成条件：条目级观察、可见校验、版本可信度与缺口列表；覆盖所选记录即完成观察，动态成立性及“安全确认”仍 inconclusive，不出全局 negative。
复核：原目标受限，写入验证阻塞于授权/身份缺失。先询问一个关键选择：是否接受已有材料观察作为本轮交付，或提供测试环境与写入授权完成动态确认？未答前不把此草稿作为原目标已就绪提交；可继续已授权材料整理。
```

## D. 必要账号缺失：阻塞草稿

输入：“验证上传的跨租户访问问题。”
上下文：A-4 允许测试租户 T-A/T-B 上的自建对象验证；E-4 基线 C4 可读；只有 `credential-ref/tenant-a` 元数据可用，T-B 的凭据引用缺失。授权资产已经明确，不重复问目标。

```text
title: 上传资源跨租户隔离验证（P-upload / C4，待补身份）
content:
目标与目的：验证 T-A 上传的自建资源是否会被 T-B 身份越权读取，交付可复核结论。
资产与基线：P-upload，测试环境 E-4 / C4（环境元数据 verified）。
范围与排除：A-4 中 T-A/T-B 测试资源；T-A 创建→T-B 请求→记录结果→T-A 清理为一条链；不触碰其他租户、真实用户或生产。
方式与前置条件：拟动态假设验证；授权 A-4 与 T-A 凭据元数据 verified；T-B 必要身份 missing，不能用同租户身份替代。
材料与引用：A-4、E-4、credential-ref/tenant-a；T-B 引用待补，不写伪造 ID。
动作与限制：条件齐备后仅最小自建样本读写与清理；当前不登录、不创建样本；禁止枚举真实资源与扩大租户范围；异常副作用立即停止。
预算：管理 Agent 规划条件齐备后 20 分钟、1 个对象、2 次跨租户请求；预留清理时间，平台上限更小时从严。
交付与完成条件：两身份元数据、对象归属、脱敏请求/响应、读取是否成功及清理证据；未取得 T-B 身份只能 inconclusive，不能宣称隔离正常。
复核：阻塞，不提交执行任务。唯一关键问题：请提供已有受治理的 T-B 测试身份引用；不索取密码。管理者补齐后重读引用元数据并复核，不重新询问 A-4 已明确范围。
```

## E. 修复后复测

输入：“上次上传那个修好了，重新验一下。”
上下文：当前项目唯一相关 F-5，原任务 T-5 / Evidence EV-5 指向 C5-old 的路径规范化问题；修复基线 C5-new 可读，测试部署 E-5 的元数据匹配新基线；A-5/M-5 允许测试租户自建对象写入和清理，凭据引用 R-5 已提供。若相关 Finding 不唯一，应先列候选并澄清，不能猜“那个”。

```text
title: F-5 上传路径规范化修复复测（C5-old → C5-new）
content:
目标与目的：复测 F-5 原触发链是否在 C5-new 消失，并检查修复邻接边界；不扩为全站重审。
资产与基线：P-upload，原基线 C5-old/EV-5，新源码 C5-new，测试环境 E-5 元数据匹配；执行前核对版本。
范围与排除：F-5 所涉上传路径及修复函数直接调用；重现原输入→保存→读取观察→清理保持一链；排除生产与无关功能。
方式与前置条件：混合复测；源码、修复差异与 E-5 元数据 verified；运行可用性待首步核验。历史 confirmed 不等于本轮仍成立或已修复。
材料与引用：F-5、T-5、EV-5、A-5/M-5、E-5、credential-ref/retest-editor（R-5）；只通过受治理凭据获取会话。
动作与限制：只在 A-5 指定测试租户使用最小自建样本，复用原无害输入并增加规范化边界反例；禁止外站与真实用户数据。执行者清理自建文件；基线不符、权限拒绝或副作用异常立即停止。
预算：A-5 上限 30 分钟、5 个样本；包括清理，不因失败无限重试。
交付与完成条件：新旧差异、原步骤本轮结果、正负对照、脱敏证据与清理记录。仅原触发条件和相邻测试充分执行才建议本轮修复有效；失败步骤区分仍可复现与环境失败，后者 inconclusive；不直接改 Verify 状态。
复核：可执行；沿用已知授权和引用，无需用户重复填表。若实际基线/会话不符，阻塞依赖验证并说明受影响判据。
```

## F. 补证而非重复探索

输入：“这条 finding 缺关键证据，补一下。”
上下文：用户指定 F-6；EV-6 缺少对象归属与请求关联，但已有授权可读的归档 H-6/L-6/I-6。A-6 仅允许离线材料读操作；无复现授权。记录标注 C6，尚未验证相互一致性。

```text
title: F-6 对象归属与请求关联补证（P-upload / C6）
content:
目标与目的：补 F-6 的对象归属和请求关联证据，判断现有材料是否足够；不重做上传全功能探索。
资产与基线：P-upload，H-6/L-6/I-6 声明 C6；先核对归档版本与时间是否一致，不能混合不同基线。
范围与排除：F-6 对应对象和关联请求；保留请求→对象创建记录→归属索引链；排除其他 Finding 和在线复现。
方式与前置条件：静态材料补证。归档可读 verified（索引）；版本关联 declared；需要但未能从档案确认的归属标 missing。动态复现非本轮动作，不能把缺失证据说成不适用。
材料与引用：F-6、EV-6、H-6、L-6、I-6、A-6；不需要凭据明文或在线会话。
动作与限制：只读授权归档；禁止重放请求与改写原证据。缺乏可靠关联键即停止推定，报告缺口；无创建对象与清理需求。
预算：管理 Agent 规划 20 分钟、最多 3 份相关材料，平台上限更小时从严；超限返回已核对范围。
交付与完成条件：每条待补主张对应证据引用、关联键与一致性检查；可证明则提交补证材料供统一复核，不足则列 missing、原因和下一步所需材料。不得用模型推断替代归属证明，也不把补证完成等同 Finding confirmed。
复核：可执行离线补证；原 finding 成立性仍受关联证据约束。缺少可靠关联时报告 inconclusive，由项目维护者补归档或另行授权复现，不借补证扩权。
```
