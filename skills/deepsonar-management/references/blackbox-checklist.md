# 黑盒与灰盒任务检查

> 状态：任务设计指南；目标身份/写授权的通用可信核验尚未接入。
> 同步日期：2026-10-29

先用[共用下发检查](task-dispatch.md)，选择 `blackbox`；有源码时可用 `graybox` 并补[白盒基线](whitebox-checklist.md)。

- 记录授权资产、环境、账号/角色/租户矩阵及目标资源归属；凭据仅使用 UUID 引用，禁止明文秘密。`identity` 是待核验声明，不是授权。
- 分清允许的只读观察与获准测试租户内的写入。save→publish→trigger 是连续状态链，不能以只读授权派发其中的写操作。
- 记录清理责任、停止条件、证据及无法验证时的交付。浏览器、HAR、JS/source map、PoC server 按需选择，不是通用必填；外联目的地须已有授权，模板不默认批准。

例如只读任务可观察已提供的脱敏 HAR/JS，声明 read 并禁止 write/egress，验收为“列出观察、证据引用、无法动态核验的步骤”。若需要访问授权目标则声明 egress，并受实际网络策略检查。不要在只读任务中要求创建或发布测试资源。

动态链需要 write、实际目标身份与资源边界、清理条件及可信授权核验。当前 Scheduler 没有通用目标身份/写权限探测器，因此此类必要条件保持未核验并阻塞；仅把 allowed_actions 改成 write 不会通过。人工补充说明也不等同于平台已经验证。

LLM flow 可作为可选场景：在获准测试环境中说明配置生命周期、状态链及节点参数的观测要求。post_process、stream 仅为具体实现示例，不作为全部平台固定字段；RCE 等结论沿用执行层证据规则，本指南不重新定义漏洞成立标准。
