# 黑盒 / 灰盒任务前置条件

黑盒任务的成败几乎全在下发前：**授权边界、账号矩阵、资源归属**写不清，执行阶段就只能靠猜范围。
灰盒（有部分源码/账号）同样适用，把已知与未知分开标注即可。

## 1. 授权与资产

| 项 | 要求 | 缺失时 |
| - | - | - |
| 授权资产 | 明确的域名 / IP / 端口 / 应用，逐项列出 | 未列出的资产一律视为**未授权** |
| 授权来源 | 项目策略或用户明确授权，能指到出处 | 不推断、不扩大；缺授权则不发起测试 |
| 出网 / PoC server | 外联目标必须在既有授权范围内 | 需要但未授权则不启动，记为 `missing`；确实无需外联才为 `not_applicable` |
| 第三方依赖 | 共享 CDN / 共用 SaaS 等，明确是否可测 | 排除并在说明里写清 |

## 2. 账号 / 角色 / 租户矩阵

- 列出本次可用的身份：`角色 × 租户 × 资源归属`，并标注每个身份**能做的动作**（只读 / 写 / 管理）。
- 明确**只读观察**与**获准的写入验证**的分界；只读身份不得用来验证写操作链路。
- 租户隔离类假设按本次验证链列出所需身份、对象及可信归属证据，不统一要求两个可登录租户账号。单身份访问获授权夹具、已有可信归属的跨租户对象、匿名访问边界可按其实际前置条件验证；只有链路确实需要另一身份而不可用时才记 `missing`（如示例 D 的 T-B 请求），不得用同租户对象或臆测归属替代。
- 凭据只写**引用**，不写明文；实际身份与租户以派发前核验为准。

## 3. 允许 / 禁止动作

写清三件事，避免执行时自行扩张：

1. **允许**：认证尝试、参数变形、只读探测、在测试租户内创建对象、上传测试文件。
2. **禁止**：修改他人数据、触发真实业务副作用（支付、通知、删除）、压测、对未列资产扫描、持久化后门。
3. **清理**：测试对象、上传文件、临时账号的清理责任与时限。

## 4. 材料与工具（按场景选，不默认全上）

浏览器 + HAR、JS / source map、PoC server、代理、移动端抓包等按探索覆盖问题或验证假设需要选择；不作为所有任务统一必填项。
选了就要写清用途与范围。

LLM / Agent 形态的流程（配置生命周期、节点参数、提示注入面）可作为黑盒场景之一，但只描述该场景的观察点，
不把它固化成所有平台的字段，也不重复定义别处的成立标准。

## 5. 完成标准与停止条件

以下是执行者的候选观察与证据交付判据，不是平台 Finding 状态。自复现只能支持主张成立，须提交证据供独立 Verify；不能据此设置 `confirmed` 或跳过平台 Verify。

| 候选观察 | 判据 | 反例 |
| - | - | - |
| 支持成立，提交独立 Verify | 可复现步骤 + 实际响应/副作用 + 影响说明；假设涉及对象归属时附可信归属证据 | 仅有疑似描述，或把自复现直接当作平台 confirmed |
| negative | 已覆盖声明的输入空间，说明覆盖方式 | 只试了一个 payload |
| inconclusive | 缺什么条件、为什么缺、需要谁能补 | 把缺条件写成 negative |

无法动态验证的写入链，明确列为**缺少条件**，不要默认放弃整条链，也不要写成「无发现」。

停止条件：已满足本轮证据判据、预算耗尽、需要未授权动作或越出资产清单、触发真实副作用——任一触发即停并记录。

## 6. 下发前自查（黑盒 / 灰盒）

- [ ] 授权资产逐项列出，未列资产视为未授权
- [ ] 账号 / 角色 / 租户矩阵明确，只读与写入动作授权已区分，必要状态链保持完整
- [ ] 允许动作、禁止动作、清理责任已写
- [ ] 材料与工具按探索范围或验证假设选择，并写明用途
- [ ] 出网 / PoC server 落在授权范围内
- [ ] 支持成立 / negative / inconclusive 三类候选观察判据可判定，明确提交独立 Verify，不直接设置平台 confirmed
- [ ] 停止条件与预算已写
- [ ] 凭据只写引用，无明文

## 7. 可选结构化契约与当前平台限制

先执行[共用下发流程](task-dispatch.md)，选择 `blackbox`；有源码时可用 `graybox` 并补[白盒基线](whitebox-checklist.md)。凭据仅使用 UUID 引用；`identity` 是待核验声明，不是授权。

例如只读任务可观察已提供的脱敏 HAR/JS，声明 read 并禁止 write/egress，验收为“列出观察、证据引用、无法动态核验的步骤”。若需要访问授权目标则声明 egress，并受实际网络策略检查。不要在只读任务中要求创建或发布测试资源。

动态链需要 write、实际目标身份与资源边界、清理条件及可信授权核验。当前 Scheduler 没有通用目标身份/写权限探测器，因此此类必要条件保持未核验并阻塞；仅把 allowed_actions 改成 write 不会通过。人工补充说明也不等同于平台已经验证。

LLM flow 的 post_process、stream 仅为具体实现示例，不作为全部平台固定字段；漏洞成立标准沿用执行层规则。
