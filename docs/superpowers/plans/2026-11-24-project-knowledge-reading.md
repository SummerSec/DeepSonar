# 项目知识阅读方案：知识卡片、使用反馈与版本选择

> 实施提案。2026-11-24 对照主线 `efa9dfc9`。本文补充[项目知识库方案](2026-11-22-project-knowledge-library.md)和 [#1219](https://github.com/SummerSec/DeepSonar/issues/1219)，实施与验收由 [#1256](https://github.com/SummerSec/DeepSonar/issues/1256) 跟踪。

## 1. 两个阅读入口

**项目成员浏览项目知识。** 复用项目「知识」页。默认按最近更新展示有权查看的在架条目，每条知识出现一次。按现象、标题词或标签搜索时，服务端按相关度和稳定键分页。支持直接打开条目或精确版本的链接。返回列表时恢复查询、标签、所选条目、焦点及滚动位置。无匹配时提供清除筛选；加载失败时保留输入并就地重试。

**任务读者回看依据。** 在任务报告结论后列出该轮任务新增、修订、实际采用的条目，显示标题和一句结论。修订项附变更理由。采用关系取自绑定精确版本的已接受评价，搜索或打开后未使用不产生关联。用条目、版本和关系去重，同一版本有多个关系可合并显示。有知识才出现这一区域。报告引用固定到当时版本；若现有新版本，同时显示“查看新版”和变更摘要。业务报告沿原有完成流程交付。

## 2. 知识卡片与评价展开

列表卡片使用当前可见版本的标题、已有核心短文、适用范围、版本号。配一行使用情况与“查看来源”。界面示例使用虚构数据：

> **归档日志按时间查为空，按请求 ID 可查**
>
> 先用一条已知请求核对时区，再判断是否缺失。适用于 v2 归档导出文件。
>
> v2 · 8 个任务用过 · 有用 5 · 部分有用 2 · 无用 1

三种评价是可点击的文字计数按钮。点击“部分有用 2”，在原卡片内显示该版本对应的日期、简短理由及可访问的来源任务，按时间倒序分页。再次点击收起。无理由的“有用”评价只展示已有事实。版本无评价时写“当前版本暂无评价”。切换版本时同步切换评价和来源，取消或忽略上一版本的迟到响应。状态与按钮用文字区分，支持键盘、触屏、屏幕阅读器和减少动态效果。

详情按需展示来源任务及证据、修改时间与理由、可访问的版本历史。搜索曝光、正文阅读、使用和分类评价次数放在“使用情况”中，标明版本、时段及去重单位。沿用 #1219 的统计定义：用过包含尝试后评为无用。一个根任务同一结论代次只有一票，版本分布按实际计票回执绑定的版本归属。人的页面访问独立于 Agent 使用账本，不增加采纳、无用票或最后一次 Agent 使用时间。页面复用已存短文和修订说明，无需为每次展示调用模型。

## 3. 同一条知识该读哪个版本

| 场景 | 选择规则 |
| --- | --- |
| 人浏览或 Agent 搜索当前经验 | 在读者有效权限与明确的目标环境内，每个条目取最新生效且适用的版本。人看核心短文；Agent 搜索仍只返回标题、标签和精确版本标识。排序先匹配相关度。 |
| 没有目标环境或无法确定范围 | 显示当前生效版本的适用范围。有多个互不相容的分支时保留一个条目入口并提示选择环境，Agent 按需补充选择条件。未知范围不宣称匹配。 |
| 旧环境仍在使用 | 例如 v3 明确只覆盖新版工具，v2 对旧环境仍有效，则旧环境命中 v2 并说明依据。仅凭版本号较旧或某次历史成功不足以继续推荐。 |
| 人从报告打开历史引用或比较修订 | 精确读取条目 ID、版本 ID 和 hash。可进入有权查看且仍被保留的所有历史版本，看到当时的结论、评价，以及现在是否已取代、已有反证或已下架。 |
| Agent 做溯源、比较或处理旧环境 | 允许按授权精确引用定向读取。常规搜索不列版本历史。运行中发布 v3 后，已经读过的 v2 保持原版本归属，评价绑定原 usage_ref。只能访问本 Job 已授权的历史引用。 |

**实施依赖。** 当前目录以活动版本指针选取本项目条目，单个指针不足以判断旧环境仍适用的 v2。沿用 #1219 的结构化适用范围，在发布/修订时记录受影响的环境和替代关系；重叠范围内取最新有效版，其他已确认仍有效的范围可继续使用旧版。缺少可信的旧范围时仅提供授权历史读取。Job 创建时冻结可读版本或精确引用，在已授权集合内选择，同时实时重核来源撤权。不得通过传入条目 ID 枚举其他项目或未授权历史。

被可信反证的版本退出默认搜索。旧报告的有权读者仍可查看历史判断和更正提示；来源撤权、安全撤销或保留期届满时按现行权限和留存策略返回可公开的不可用状态，不展示受限标题、评价理由或证据摘要。列表、排序、总数、反馈统计和版本历史均须先过滤权限。

## 4. 工程切分

| 顺序 | 实施落点 | 交付条件 |
| --- | --- | --- |
| 1. 版本与读取契约 | 对照 [目录冻结](../../../apps/scheduler/src/domains/project-knowledge/catalog-snapshot.ts)、现有知识操作及 PostgreSQL 版本/来源/使用表。复用既有项目列表、版本列表和精确版本详情接口，实现适用版本选择、来源复核及精确历史读取。 | 提供当前、旧环境、未知范围、历史、反证及撤权的契约用例，人和 Agent 的选择一致。 |
| 2. 项目阅读页 | 扩展 [项目知识 API](../../../apps/web/src/ProjectKnowledgeApi.ts) 与[项目知识页](../../../apps/web/src/pages/ProjectKnowledgePage.tsx)。列表按页批量返回版本短文、适用范围与三类评价计数；反馈明细按版本、评价类型及游标查询。 | 首屏一次分页请求获取卡片所需数据，点击反馈再请求明细。已有后台活动放在按需入口。普通用户无须审批或手动整理条目。 |
| 3. 报告引用 | 从任务轮次内已接受的创建、修订和评价回执投影关联，报告阅读器按原任务权限加载。链接带精确版本，支持回到原报告位置。与正在进行的报告页面改动对齐入口。 | 报告在发布新版后仍显示当时使用的版本。空态、来源失效、历史未留存均可正常阅读报告。 |
| 4. 验收与文档 | 实现时更新项目知识专题、FR-KNOW-001 追溯、数据/接口/安全视图及对应 Actions 套件。复用 #1219 的三类评价和计票结果。 | 保存 API/SQL、界面交互和真实预览的验证记录；工程验证与真实使用收益分别报告。 |

先交付一条真实链路：项目搜索 → 读卡片 → 查看来源 → 返回原位置。随后接上版本切换、评价展开与报告入口。[已合入的读取操作更名](https://github.com/SummerSec/DeepSonar/pull/1227)可直接复用。#1219 下的创建、反馈和统计按其实际合入状态接线。无数据时展示零样本或未取得，不用合成数据填充产品界面。

## 5. 验收场景

1. 一个新成员仅凭现象找到条目，在列表直接读到结论与适用条件。详情链接可分享，接收者仍受自身权限约束。
2. v2 有 8 个任务评价，v3 刚生效。默认卡片展示 v3 和“当前版本暂无评价”。切到 v2 才显示 8 条对应记录。仅适用 v2 的任务仍能按范围检索，有可信反证后 v2 退出默认搜索。
3. Agent 读 v2 后发布 v3，评价仍归 v2；任务报告精确打开 v2 并能导航至有权访问的新版。人反复打开历史、展开反馈均不延长闲置期限。
4. 查询、评价气泡和版本切换均覆盖空、加载失败、重试、快速连续点击和迟到响应。项目切换、撤权后不能通过条目计数、来源标题、反馈或旧链接泄露数据。
5. 实现者在隔离预览走通搜索、读来源、回到列表及从报告打开旧版。核对宽窄屏、键盘、深浅色、减少动态效果下的焦点和滚动；在长列表快速展开收起时记录布局偏移或帧耗时。跨页面交付安排独立复核。可验收目标是读者能从原任务找到具体判断并核对当时依据。
