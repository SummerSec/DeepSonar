# 0021 只登记成功任务的知识来源并提供历史预览

> 状态：**已采纳**（2026-11-09 用户明确收敛本轮范围；工程验证以最终 SHA Actions 为准）。
> 同步日期：2026-11-09

## 背景与决定

本决定取代 [0020](0020-scheduler-knowledge-triggers.md) 的自动整理执行与写入式历史补做。本轮只保留成功来源登记、Barry 全局 Git Skill 源的既有同步接入和只读历史资格预览。项目批处理、整链 token 预算及 schema 变更暂缓。

成功业务 Job 在原终态事务内复用 append-only `audit_logs` 登记来源元数据，以 Canvas→Job 锁和查询避免重复。只写 Job、Attempt、Canvas 引用和来源类型存在标记；不复制 Fact/Evidence 正文，不创建 work、Canvas 或模型 Job，不发送整理唤醒。登记失败以 savepoint 隔离并告警，不回滚业务成功。

历史预览只查询现有 Job、来源是否存在、冻结权限、最新 Attempt 和未结算效果，并返回登记与已有 work。不存在 POST 执行入口。历史来源不因预览被登记；元数据登记不保证内容保留，来源删除后可能无法补做。旧自动 work 和预算历史保留，调度器不再自动开始这些 work 的后续阶段；本轮不取消在途 Job 或重置预算。既有 Agent 显式请求整理仍使用原流程。

全局 Git Skill 源复用 trusted + enabled 接入；接入公开上游 Skill 不代表业务任务新沉淀，也不自动回写 GitHub。

## 取舍与注意力成本

复用现有审计记录和读取权限，减少新状态机、配置和运维负担。登记与整理分开后，用户需要知道当前只发现来源，尚未完成知识产出；接口因此明确展示当前资格、原因及已有 work。批量整理和成本控制待单独范围确认后交付。

## 验收

知识集成入口覆盖重复/并发登记、失败隔离、项目权限、分页、敏感正文不返回、历史预览无写入、无 POST 及旧自动 work 不派发。schema、模型网关和共享预算契约无改动；所有测试、构建和 typecheck 仅在 GitHub Actions 执行。
