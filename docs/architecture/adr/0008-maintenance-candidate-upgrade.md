# 0008. 维护升级以数据库身份隔离、候选库与激活回执保护已接受写入

> 状态：**已采纳；实现接线与端到端验收进行中**
> 决策日期：2026-10-21
> 同步日期：2026-10-21
> 来源：#740 / #747；用户明确允许维护模式暂时拒绝新任务入队及其他业务写入
> 关联需求：CON-003 / FR-JOB-004 / FR-JOB-010 / IR-009 / NFR-REL-008

## 背景

[ADR 0007](0007-paused-upgrade-recovery.md) 的暂停领取仍允许业务写入，因而不能自动恢复旧备份。本轮用户已批准维护模式。此授权不包括现网操作、发布、隐式清除配置，也不等于允许把激活后已接受的新写入丢弃。现有 schema rebuild 是多阶段提交，不能以一个外层事务假装原地重建原子化。旧 Compose 的共享运行身份可能是 PostgreSQL 初始化超级用户；仅 HTTP 门禁或只读默认参数无法阻止旧进程写库。

## 决策

1. 官方发布清单、不可变镜像来源和配置预检仍在维护前核验。只读 schema plan 绑定源结构、可信当前镜像 baseline SHA、目标 schema SQL SHA、目标版本和显式风险选项；动态行数不进入稳定审批 hash。维护许可不自动批准删除数据或重置角色身份；风险必须以匹配的计划 hash 明确批准。
2. 先暂停领取并排空在途任务及所有 Attempt 的未结算/未知效果，不自动杀 Job。再通过独立维护身份禁止旧运行身份 LOGIN、清退其全部数据库会话并验证隔离事实，建立备份切点。不能按 application_name 仅停止 Scheduler 而漏掉 ImageAdmission 或旧节点。PostgreSQL 不允许降低初始化角色权限时，保留其权限但持续禁止登录；新的运行身份不继承该超级用户身份。
3. 源库冻结保留，不原地恢复或重建。验证压缩备份后恢复到独立、明确归属的候选库，目标镜像只重建候选。候选恢复/重建意图和完成回执必须持久化；仅在归属、源库隔离、候选无业务写入且尚未激活均获证实时，才能重建本操作的中断候选。无归属对象保留，不猜测后删除。
4. 新服务以 generation 绑定的 `preparing` 状态验证目标版本、schema、HTTP 和 Web；业务 HTTP、WebSocket 及后台执行在维护态关闭。服务进程门禁不能替代数据库隔离；运行角色、世代和版本不符时拒绝执行。所有受管节点准备并验证后才跨越唯一激活边界。
5. 同目标续做使用持久 journal 的目标 digest、plan hash、generation 和部署身份，不重新追随最新发布。每一步复验实际效果；本地 receipt 缺失不能证明操作未发生。激活结果不明保持停写并对账。已有激活证据时不得切回冻结源库；故障只允许保留当前代数据的前向修复。
6. 激活前失败可以恢复源库和旧镜像，但使用新的受限运行身份，旧身份不重新启用；完成后保持暂停。释放回滚后的暂停必须是显式操作并复验恢复目标与排空状态，不能在 finally 中自动恢复。完全未发生暂停/隔离的失败可返回原部署未改变，不虚报已暂停。

本决策扩展 ADR 0007 的“仅同 schema、无远程节点、无自动续做”适用限制；它保留该 ADR 的不抹除合法写入和回滚保持暂停原则。旧 ADR 决策正文不改写。单一基线、无启动增量迁移链和不向后兼容约束保持成立。

## 状态

已实现基础模块：数据库身份隔离、候选恢复/重建、只读 plan CLI、维护状态机、服务维护门禁及受管节点执行模块；宿主生产入口、受管 SSH 节点编排和显式回滚恢复领取正在整合。源码中 schema 编号是当前集成基线，不表示已发布版本；合入并行 schema 变更后须重新核对唯一编号及 DDL 指纹。

候选模块单测、状态机故障注入和隔离 PostgreSQL 候选重建已有执行证据；它们不能替代最终真实双版本 Compose、多节点 SSH、激活响应丢失和回滚恢复领取的完整端到端验收。P2 签名/无人值守升级、P3 Web 发起未完成。

## 后果

- 备份切点后、激活前没有已接受的业务写入，源库因而是可核验的回滚依据；激活后不再作此假设。
- 增加维护身份、每代受限运行凭据、候选存储、私有恢复文件和节点清单的运维成本。密钥不写入 journal、命令参数或诊断输出。
- 受管 SSH 清单必须与登记节点、固定主机身份、部署路径及目标版本绑定；不允许旧节点自动重新登记为当前代。未受管节点不是可安全自动升级的节点。
- 配置 preflight 只验证声明覆盖范围，已检查声明字段 URL/枚举和必需主密钥只读文件元数据；不验证密文解密、文件密钥内容/格式、凭据或外部服务真实认证、registry 可拉取性、历史 Job 快照语义、未知环境扩展、原生 Provider 扩展或 Skill 源内容。未知项不标记为完整兼容性通过。
- 验收入口：[维护状态机测试](../../../deploy/platform-upgrade-maintenance.test.mjs)、[数据库身份实测](../../../deploy/platform-upgrade-database.integration.test.mjs)、[候选测试](../../../deploy/platform-upgrade-candidate.test.mjs)、[schema 实测](../../../apps/scheduler/src/platform-upgrade-schema-integration.test.ts)、[维护 Compose 演练](../../../deploy/platform-upgrade-maintenance.integration.mjs)。当前验收状态见[风险记录](../12-risks-and-tech-debt.md)。

## 替代方案

只暂停领取或只加 HTTP 维护门禁：无法阻止旧节点和现有数据库连接写入，拒绝作为数据库隔离。原地重建并在失败时恢复旧备份：多阶段中断和恢复点后写入难以证明无损，改用源库保全与候选库。激活响应丢失即自动回旧：可能覆盖已经接受的写入，拒绝。通过 `force` 隐式清除角色身份或接受同版本不同 DDL：没有对应审批与来源证据，拒绝。
