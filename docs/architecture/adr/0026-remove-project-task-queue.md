# ADR 0026 删除项目任务队列并统一普通调度

> 状态：已采纳；取代 ADR 0019 及 ADR 0022 的 FIFO 占位/让位部分；最终 SHA Actions 待验。
> 决策日期：2026-11-21（本轮实施口径确认；#1180 已先行记录删除决定）
> 同步日期：2026-11-21
> 来源：#1180 及升级安全意见；FR-TASK-008、FR-CTRL-006、NFR-UX-001、CON-003。

## 背景

用户明确要求完整删除项目任务队列，减少与现有并发设置并存的操作和理解成本。完整任务串行资格与 Job 并发粒度不同，本决定不将其描述为并发计算缺陷。旧队列暂停与任务自身暂停不同，直接丢弃旧状态可能擅自启动待办。

## 决策

完整移除队列 UI、API、共享契约、权限/路由映射、Scheduler 资格/占位/推进/对账及重试和人工续做依赖；当前数据库基线删除全部队列专属结构。无兼容返回、运行时旧表读取、隐藏功能或替代开关。旧 ADR 原决策正文保留作历史。

任务统一使用既有 Scheduler。全局、项目、Provider、凭据、模型、Agent CLI 并发、定时、跨项目公平领取、锁和 Job/Attempt 生命周期继续权威；任务暂停/取消、重试、报告与人工续做保留原权限、预算、租约、未知效果及终态门。人工等待不阻塞其它任务，无需显式让位；回复先保存，原恢复准入决定唯一后继。

schema 79 受控重建仅对旧队列 paused=true 的非成功条目投影任务暂停，含无活动 Job 的 active 及已封存 waiting_human；仅 claimed/provisioning/running 的 Canvas 排除投影。已有 execution_control.paused=true 的控制内容原样保留，其余命中者设为任务暂停。已确认失败且队列恢复者不再暂停，原可执行待办交普通调度。暂停任务以后由有权限操作者沿既有任务继续执行入口恢复，不把删除当作启动同意。

无法识别旧队列结构时须在破坏性操作前拒绝，不猜测停止意图。PR 1204 防止丢失停止意图的保护目标由 PR 1208 的投影与提前拒绝承接，不采用一律阻止删除旧结构的方案。这是删除旧结构前的停止意图保全，不是兼容窗口。沿用受控 schema 重建、备份、回滚及旧库启动拒绝。运行中身份保持，不重复领取、不重放效果、不改写历史冻结快照。任务、Job/Attempt、Evidence、报告、审计及人工请求/回复保留。实现、契约、界面与文档同批整合，不交付仍调用已删除 API 或读取已删除表的部分状态。

## 后果与验证

- 收益：减少一套配置、顺序和阻塞原因，复用现有调度与任务控制，不新增设置或通知；注意力收益尚未实测。
- 代价：不再保证项目完整任务 FIFO 串行，旧控制不受支持。升级保全为任务暂停的待办需显式继续，删除不等于启动授权。
- 验收：普通并发上限/释放、多 Scheduler 唯一领取、定时与任务控制、人工续做、旧基线七类夹具及 waiting_human、历史一致性与契约删除，见[专题](../../PROJECT_TASK_QUEUE.md#决策与验收边界)。最终 SHA Actions 待验，本地不执行测试、构建、typecheck 或数据库重建；未部署。

## 替代方案

以下为本轮分析，不冒充历史讨论：隐藏入口或默认关闭留下隐藏阻塞；保留旧 API/表兼容违反完整删除决定；直接丢弃停止意图可能擅自启动；另建队列恢复状态机增加复杂度。采用完整删除并保全到现有任务暂停。
