# ADR 0019 项目队列通过既有领取事务授予任务执行资格

> 状态：已采纳，本次实现的工程验收以最终 SHA Actions 为准。
> 同步日期：2026-11-09

## 背景

#1018 要求把多个任务排队，前一任务结束后自动开始下一项。一个 Canvas 可以包含多轮 Hub、并行 Worker、Verify、Report 和恢复过程，单个 Job 结束无法证明整个任务已经结束。

## 决策

项目采用一个可选持久 FIFO 队列。PostgreSQL 保存顺序、暂停与占位，Scheduler 的全局 claim 事务锁统一串行化队列控制和执行资格判定。真实领取首个 Job 后标记当前 Canvas 占位，内部 Job 继续使用原并发和生命周期。

Root 的治理成功、当前报告（存在时）、本轮工作代际、活动 Job 和未结算效果共同约束释放。人工等待、任务暂停和未知效果保留位置。失败/取消默认暂停，明确继续必须确认当前失败条目 ID，陈旧确认不能跳过后来失败的任务。治理恢复后完整成功按成功策略推进。

当前任务的内部工作可在队列暂停时继续，任务自身暂停仍由原执行门控制。手动暂停独立于任务失败后的自动暂停，治理恢复成功不能撤销已有手动暂停。终态任务的新合法 pending 工作重新排尾，旧 Root/Report 的成功不能为新工作背书。队列不拥有 Job/Attempt、效果结算或模型控制权限。

## 后果与验证

schema 72 增加项目队列与条目，项目/Canvas 复合外键和单 active 唯一索引构成数据约束。新任务首 pending Job 与队列记录同事务，队列不产生第二执行通道。用户从任务页查看顺序和阻塞原因，失败确认只在确需跳过时出现。
