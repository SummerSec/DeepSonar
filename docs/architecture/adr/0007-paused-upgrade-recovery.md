# 0007. 同 schema 升级回滚保留数据库并保持暂停

> 状态：**已采纳**（#747 当前实现边界）
> 决策日期：2026-10-20
> 同步日期：2026-10-20
> 来源：#740 / #747 / [宿主升级状态机](../../../deploy/platform-upgrade.mjs)
> 关联需求：FR-JOB-004 / FR-JOB-006 / FR-JOB-010

## 背景

暂停领取仍允许新任务入队及管理写入。Attempt 终态也不证明外部效果已结算。自动恢复暂停时的旧数据库备份，会抹掉暂停后合法写入；恢复领取请求的响应丢失则可能已经放行新 Job。

## 决策

宿主自动切换仅支持同 schema、单控制面、无远程 worker 的稳定版本升级。必须先核对官方平台清单、拉取镜像、预检、通过管理 API 暂停并排空所有 Attempt 的未结算/未知效果，再验证备份并切换。停止容器前直接校验本地数据库仍暂停且已排空；API 地址指错部署时不得停止本地服务。切换后的 readiness 允许最多 180 秒启动等待，超时保持暂停。跨 schema 在暂停前拒绝，不引入增量迁移或旧契约兼容。

同 schema 回滚必须保留现有数据库，只恢复记录中的镜像引用；回滚前仍须验证暂停与排空，完成后必须保持暂停等待人工核验。备份供人工离线灾难恢复，不得自动恢复旧数据库。调用恢复领取 API 前必须持久记录意图；响应不明时禁止自动回滚或假定仍暂停，转人工对账。失败与中断不得在 finally 中解除暂停。

## 状态

2026-10-20 随 #747 实现。未完成跨 schema、多节点、完整配置兼容性 preflight 与自动中断续做；不据此宣称 #740 全部完成。无历史 ADR 被取代。

## 后果

- 保留暂停期间新写入，避免未知外部效果与恢复领取响应丢失导致重复执行。
- 中断后需要显式 rollback 或人工对账，不能保证自动恢复可用性；备份处理上限 512 MiB。
- 验收：[升级故障注入测试](../../../deploy/platform-upgrade.test.mjs) 接入 `pnpm ci:unit:deploy-ps1`；[真实数据库排空回归](../../../apps/scheduler/src/domains/platform-claims/platform-claims.integration.test.ts) 接入 `pnpm ci:integration:dispatch-limits`。真实双版本部署演练仍需独立环境，不能由 mock 通过推定。

## 替代方案

当前评估过自动恢复旧备份：因暂停不禁止写入而拒绝。当前评估过失败后自动解除暂停：可能在镜像或外部效果未知时重新领取，故拒绝。跨 schema 的离线写入冻结与恢复协议留待后续实现，不在本决策中声称已落地。
